# Petali e Fiori

Redesign of https://www.petaliefiori.it/ as a warm, modern website for the flower shop in Via
Arzaga 24, Milan. React with Vite on the front end, Express behind it, MySQL for content and
custom CSS for the visual language. Every phase of the project is a session, the plan lives in
ROADMAP.md and the working rules live in AGENTS.md.

## Stack

- Front end: React 18 with Vite, function components, hooks, custom CSS.
- Back end: Express 4 with ESM modules, mysql2 connection pool, no ORM.
- Database: MySQL 8, designed with MySQL Workbench.
- SEO: sitemap.xml and robots.txt generated by the server, server side rendering in Session 6.

## Requirements

- Node.js 18 or newer (tested on Node 24).
- MySQL 8 with a user that can create the database, MySQL Workbench is the recommended client.

## Install

```bash
npm install --prefix server
npm install --prefix client
```

## Database

```bash
npm run seed
```

This applies db/schema.sql, db/seed.sql and db/seed_gallery.sql in order and rebuilds every
content table. contact_messages is never truncated, so real messages survive a re seed.

## Development

```bash
npm run dev
```

Runs the API and the Vite dev server together: the API on http://localhost:3001 and the site on
http://localhost:5173. Vite proxies /api, /sitemap.xml and /robots.txt to the API, so the
browser only ever talks to one origin. To start only the API:

```bash
npm start
```

## Tests

```bash
npm test
```

Runs the API acceptance tests in server/test against the local database. Seed first, they
assert the real content and they remove every contact message they create.

## Environment variables

Copy .env.example to .env and adjust it. Values already present in the real process
environment win over the file.

| Variable | Default | Purpose |
| --- | --- | --- |
| PORT | 3001 | Port of the API |
| SITE_URL | https://www.petaliefiori.it | Public origin for canonical links, sitemap and Open Graph |
| CLIENT_ORIGIN | http://localhost:5173 | Browser origins allowed to call the API, comma separated |
| DB_HOST | 127.0.0.1 | MySQL host |
| DB_PORT | 3306 | MySQL port |
| DB_NAME | petali_e_fiori | Database name |
| DB_USER | root | Database user |
| DB_PASSWORD | empty | Database password |
| MYSQL_BIN | empty | Optional path to the mysql client used by npm run seed |
| CONTACT_RATE_LIMIT | 10 | Contact posts allowed per IP every 15 minutes |
| NODE_ENV | development | Set to test to disable request logging |

## API endpoints

All endpoints answer JSON. Collections are wrapped in a resource key, single resources too,
and errors answer `{ "error": "message" }`.

| Method | Path | Description |
| --- | --- | --- |
| GET | /api/health | Status of the service and of the database, 503 when the database is down |
| GET | /api/settings | Shop facts as a key/value object, 30 keys |
| GET | /api/pages | Published pages without the long body |
| GET | /api/pages/:slug | One page with intro, body, meta title and meta description |
| GET | /api/services | Published services ordered by menu group |
| GET | /api/services/:slug | One service with the full body |
| GET | /api/bouquets | Bouquet models with price ranges, optional ?style=decorativo |
| GET | /api/decorations | The decoration types with description and best use |
| GET | /api/price-examples | Real price examples, items come back as an array |
| GET | /api/gallery | Gallery images, optional ?category=chiesa, plus category counts |
| GET | /api/partners | Shop partners |
| POST | /api/contact | Stores a contact form message, see below |
| GET | /sitemap.xml | XML sitemap built from the published routes |
| GET | /robots.txt | Robots file pointing at the sitemap |

Image paths inside the payloads (hero_image, image, file) are relative to the /images prefix
that the client serves from client/public/images, so `bouquet/bouquet-degas.jpg` is displayed
as /images/bouquet/bouquet-degas.jpg.

### POST /api/contact

Accepted body:

```json
{
  "name": "Nome e Cognome",
  "email": "email@example.com",
  "phone": "331 8603337",
  "wedding_date": "2027-06-12",
  "venue": "Luogo dell'Evento",
  "message": "Testo del messaggio",
  "website": ""
}
```

name, email and message are required, the rest is optional. The server rejects missing fields,
invalid emails, values over the column size and invalid dates with 400 and a `fields` object
that maps each field to its Italian error message. `website` is the honeypot: the real form
has no such field, a bot that fills it gets a 201 answer and nothing is stored. Every attempt
counts against the rate limit, and after the limit the answer is 429 with a Retry-After
header.

Successful answers return 201 with `{ "ok": true, "message": "Grazie, abbiamo ricevuto..." }`
and the message lands in contact_messages.

| Route | Source |
| --- | --- |
| / | Static home page (Session 4) |

## Front end

The client is a Vite React app in client/, run it with the root `npm run dev` or on its own with
`npm run dev --prefix client`.

- client/src/routes.js holds every canonical path plus the header and footer navigation.
- client/src/api/client.js wraps fetch: it raises ApiError with the Italian message and the
  `fields` object returned by the server. Paths are relative, the Vite proxy and production
  Express both serve the API under the same origin.
- client/src/context/SettingsContext.jsx loads /api/settings once and falls back to the shop
  facts of ROADMAP.md section 3 while the API is loading or unreachable.
- client/src/styles/tokens.css holds the palette, the type scale and the spacing, base.css the
  reset and typography, layout.css the container, sections and the 12 column grid. Components
  carry their own CSS file next to the component.
- Every text pair used in the interface passes WCAG AA, verified with a contrast audit over the
  rendered pages. Warm accents used as text come from --text-accent, never from the pure
  apricot or rose of the palette.

To check a page in a browser during development, the API must be running so the pages can read
their content from MySQL.
